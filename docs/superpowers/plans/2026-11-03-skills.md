# Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workspace can add skills four ways (upload, type, generate with its own model, copy a pre-built one), enable them per bot, and an agentic bot loads a skill's instructions only when it needs them.

**Architecture:** Laravel owns `skills` and `bot_skills` plus a Skills page per workspace. Skill files use the Agent Skills `SKILL.md` format (front matter `name`, `description`, optional `tools`). The engine lists the bot's available skills (name + description) in the agent loop's system prompt and offers one built-in tool, `load_skill`, that returns a skill's body.

**Tech Stack:** Laravel 13 / PHPUnit, PHP `ZipArchive`; FastAPI, pytest.

**Spec:** `docs/superpowers/specs/2026-11-03-agentic-design.md` (section 3; category 4)

**Depends on:** Tasks 1–3 are independent and can start now. Task 4 needs `agent.py` from `docs/superpowers/plans/2026-11-03-agentic-core.md`.

## Global Constraints

- Format: `SKILL.md`, front matter between `---` lines with `name` (`^[a-z0-9-]{1,64}$`), `description` (≤ 1,024 chars), optional `tools` (comma list or `[a, b]`) naming connector tool names. Body ≤ 50,000 chars.
- Front matter is parsed as simple `key: value` lines; no YAML library (`symfony/yaml` is not installed). Mark it `ponytail: key: value front matter only; add symfony/yaml if real skills need nested YAML`.
- Upload: `.md` or `.zip` (≤ 1 MB) containing `SKILL.md` at the root or one folder deep. Other files in the zip are ignored, and the page says so.
- Origins: `upload`, `typed`, `generated`, `builtin`. Built-ins have `system_id = null`, are read-only, and are copied into a workspace to be used.
- Skill text is data: the engine skips any skill whose body `shield.detect` flags, and logs it.
- A skill is offered to a bot only when every tool it names is enabled for that bot.
- Manage: workspace `system_admin`; editors pick skills on a bot.

## Review Focus

- A `SKILL.md` with Windows line endings, a BOM, or no front matter → BOM/CRLF handled; no front matter is a 422 naming the missing `name`.
- A zip with `../SKILL.md` or two `SKILL.md` files → refused with a sentence, nothing written to disk.
- A skill naming a tool the bot does not have → shown on the Behaviour tab as unavailable ("needs: create_ticket"), never sent to the model.
- `load_skill` with a name that is not one of this bot's available skills → error result, no body leaked from another workspace.
- Generating a draft when the provider is down → a sentence in the modal, nothing saved.

### Task 4: Skills in the agent loop and on the Behaviour tab

**Files:**
- Modify: `api-engine/agent.py`, `api-engine/sources/attempts.py` (pass skills into `agent.run`), `BotBrainController.php` + `bots/brain.blade.php` (Skills checklist inside the Agentic card; unavailable skills disabled with "needs: …")
- Test: `api-engine/tests/test_agent.py`, `admin-laravel/tests/Feature/AgenticSettingsTest.php`

**Interfaces:**
- Consumes: `agent.run(..., extra_system=...)`, `agent.Tool`.
- Produces: `async def skills_for(session, bot, tool_names: set[str]) -> list[SkillRow]` — the bot's linked skills whose `tools` ⊆ `tool_names` and whose body `shield.detect` does not flag (flagged ones printed `[Skills] Skipped {name}: reads as instructions`). `def skills_prompt(skills) -> str` — `"Skills you can load with load_skill when a request matches:\n- {name}: {description}"`, empty string when none. `agent.run` gains `skills: list = ()` and sets `extra_system = skills_prompt(skills)`. When skills exist, `run` adds a built-in function tool `load_skill(name: string)`; its result is the body wrapped with `spotlight.wrap`; it does not count toward `agentic_max_calls` and is not logged to `chat_tool_calls`. An agentic bot with skills but no connector tools still runs the loop.
- Brain validation: `skills` array of ids from the bot's workspace; linking one whose tools are not all enabled is allowed but shown unavailable.
